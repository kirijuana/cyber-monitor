# 🛡️ Cyber Monitor — Платформа мониторинга инфраструктуры

Модульная платформа мониторинга с интеграцией различных сервисов: Dr.Web, Bitrix24, почта и другие.

## ✨ Возможности

### Реализовано

- ✅ **Главный дашборд** — сводка по всем системам мониторинга
- ✅ **Dr.Web мониторинг** — полный контроль антивирусной защиты
- ✅ **Детальный анализ станций** — информация о сервере, угрозах, компонентах
- ✅ **Фильтрация станций** — по статусу, наличию угроз
- ✅ **Современный UI** — glassmorphism, градиенты, анимации

### Планируется

- 🔄 График угроз по времени
- 🔄 HIPS-события
- 🔄 Карантин
- 🔄 Лицензии с предупреждениями
- 🔄 Bitrix24 интеграция
- 🔄 Почтовый сервер
- 🔄 Zabbix

## 📊 Страницы

### 🏠 Главный дашборд (`/#/`)
- Сводка по Dr.Web (всего станций, защищено, внимание, критично)
- Карточки сервисов с статусами
- Быстрый переход к детальной информации

### 🛡️ Dr.Web (`/#/drweb`)
- **Информация о сервере** — имя, версия, uptime, память, диск
- **Статистика** — защищено/внимание/критично/с угрозами
- **Фильтры** — все/с угрозами/без угроз/критические
- **Список станций** — с счётчиком угроз и кнопкой "Анализ →"

### 🔍 Анализ станции (`/#/station/:id`)
- **Полная информация** — пользователь, отдел, организация, город
- **Угрозы** — сгруппированы по типу с иконками и уровнем опасности
- **Компоненты** — запущенные службы
- **Группы** — к каким группам принадлежит станция
- **Статистика** — вирусные базы, записи вирусов, дата создания

### 💼 Bitrix24 (`/#/bitrix24`)
*В разработке* — мониторинг CRM и бизнес-процессов

### 📧 Почта (`/#/mail`)
*В разработке* — мониторинг почтовой инфраструктуры

### ⚙️ Сервисы (`/#/services`)
Статус всех компонентов инфраструктуры

## 🚀 Быстрый старт

### 1. Клонирование

```bash
git clone https://github.com/kirijuana/cyber-monitor.git
cd cyber-monitor
```

### 2. Сборка фронтенда

```powershell
# Windows
.\build.ps1

# Или вручную
npm install
npm run build
```

### 3. Установка Python зависимостей

```bash
cd backend
pip install -r requirements.txt
```

### 4. Настройка Dr.Web

Открой `backend/main.py` и заполни свои данные:

```python
DRWEB_URL = "https://10.4.0.115:9081"  # IP/порт Dr.Web сервера
DRWEB_USER = "admin"                     # Логин
DRWEB_PASS = "password"                  # Пароль
```

### 5. Запуск

```bash
cd backend
python main.py
```

Открой: **http://localhost:8001**

## 🔌 API Endpoints

| Endpoint | Описание |
|----------|----------|
| `GET /` | Главная страница (SPA) |

| `GET /api/station/{id}` | Детали станции с угрозами |

## 📝 Добавление нового сервиса

1. Создай клиент в `backend/` (например `bitrix_client.py`)
2. Добавь эндпоинт в `main.py`
3. Создай страницу в `src/pages/`
4. Добавь маршрут в `src/App.tsx`
5. Добавь пункт меню в `src/components/Sidebar.tsx`
6. Обнови `/api/dashboard` для отображения на главной

## 🐛 Troubleshooting

### Белый экран
- Запусти `npm run build` чтобы собрать фронтенд
- Проверь что файлы есть в `frontend/`

### API не отвечает
- Проверь что бэкенд запущен
- Проверь настройки Dr.Web в `main.py`
- Открой DevTools (F12) и проверь консоль

### Угрозы не отображаются
- Проверь логи сервера — там будет информация о запросах к Dr.Web API
- Убедись что у пользователя есть права на получение статистики
- Проверь что на станциях есть обнаруженные угрозы

### Ошибки сборки
- Удали `node_modules/` и выполни `npm install` заново
- Проверь версию Node.js (рекомендуется 18+)
