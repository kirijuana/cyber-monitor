# Техническое задание на систему мониторинга

## 1. Общее описание

Веб-приложение для централизованного мониторинга ИТ-инфраструктуры с модульной архитектурой.

**Первая итерация:**

- Главный дашборд
- Страница Dr.Web

**Планируемые расширения:**

- Bitrix24
- Почтовый сервер
- Zabbix
- Прочие источники

---

## 2. Целевая аудитория

- **Системные администраторы** — основные пользователи
- **ИТ-руководители** — обзорные метрики
- **Дежурная смена** — быстрый статус

## 3. Функциональные требования

### 3.1. Главный дашборд

**Назначение:** сводка по всем системам мониторинга на одном экране. Позволяет за 5 секунд понять, всё ли работает.

**Компоненты:**

| Виджет | Тип | Данные | Источник |
|--------|-----|--------|----------|
| Общий статус систем | Индикатор (зелёный/жёлтый/красный) | Агрегированный статус по каждой системе | Все модули |
| Станции Dr.Web: онлайн/оффлайн | KPI + мини-график | online / offline / total | `/api/server/` |
| Угрозы за 24ч | KPI с трендом | infections-chart | `/api/stations/infections-chart.ds` |
| Карантин | KPI | Количество объектов | `/api/quarantine/` |
| Новые станции | KPI | newbies count | `/api/server/` |
| События (лента) | Activity feed | Последние события из всех систем | Агрегатор |
| Инциденты | Список | Критические события | Агрегатор |

**Дизайн-принципы:**

- Информационная иерархия: важное — вверху и крупнее
- Баланс контента и whitespace
- Прогрессивное раскрытие: клик по KPI → детализация
- Live-индикатор: зелёный пульс (idle), синий (syncing), жёлтый (stale)

### 3.2. Страница Dr.Web

**Назначение:** полный контроль антивирусной защиты для ежедневной работы администратора.

**Секции:**

**A. Сводка по серверу**

- Имя, версия, uptime, ОС, платформа
- Память: total / free / used_by_server
- Файловая система: свободное место

**B. Станции**

- Таблица с фильтрами: статус, группа, ОС, ошибки обновления
- Колонки: имя, группа, статус, последнее подключение, версия ПО, компоненты
- Действия: перезагрузка, сканирование, восстановление

**C. Угрозы и события**

- График infections-chart по времени (день/неделя/месяц)
- Таблица HIPS-событий
- Топ угроз (statistics.ds)

**D. Карантин**

- Список объектов с деталями
- Действия: восстановить, удалить

**E. Лицензии**

- Статус ключей, срок истечения
- Предупреждения за 30/14/7 дней

**F. Репозиторий**

- Статус обновления баз
- Продукты в репозитории

**Технические особенности:**

- Авто-обновление: polling каждые 30–60 сек
- Ручной refresh с индикацией загрузки
- «Stale» состояние: если данные старше 5 минут — «Stale · X min ago»

## 4. Нефункциональные требования

**Производительность:**

- Время загрузки дашборда: < 3 сек
- Авто-обновление без перезагрузки страницы
- Виртуальный скроллинг для больших таблиц

**Адаптивность:**

- Desktop-first
- Responsive-вёрстка для планшетов

**Безопасность:**

- Аутентификация (сессия или JWT)
- Роли: admin / viewer
- API-ключи внешних систем хранятся server-side

**Расширяемость:**

- Модульная архитектура: каждый источник — отдельный адаптер
- Единый интерфейс адаптера: `fetchMetrics()`, `fetchEvents()`, `getStatus()`
- Общий формат метрик:

```
{ timestamp, source, metric, value, severity, metadata }
```

## 5. Технологический стек

| Слой | Технология | Обоснование |
|------|------------|-------------|
| Frontend | React + TypeScript | Компонентность, экосистема |
| Стили | Tailwind CSS | Быстрая итерация, утилитарный подход |
| Графики | ApexCharts / Recharts | Простые графики, интерактивность |
| Сложные визуализации | D3.js | Полный контроль, кастом |
| Build | Vite | Скорость сборки |
| Backend | Node.js / Python | Адаптеры для API |
| Real-time | WebSocket / SSE | Live-обновления |
| Хранилище | PostgreSQL + Redis | История метрик + кэш |
